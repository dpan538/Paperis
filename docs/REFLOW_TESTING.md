# 文本重排如何验证

重排分成两个可独立检查的阶段：从文档提取可读正文，以及把正文分配到行、栏与页。页面看起来整齐不足以证明文字准确。

## 解析后的正文

`androidTest/assets/fixtures/golden/expected.txt` 是人工编写的文本真值，包含中文、英文、数字、标点、补充平面汉字和 emoji。对应的 UTF-8、UTF-16 LE / BE、GB18030、Markdown、HTML、EPUB 与 DOCX 小样应逐字产生相同结果。

EPUB 故意让文件名顺序与书脊顺序相反，以检查章节是否按书脊连接。HTML 含不应进入正文的 script/style。PDF 另用已知内容的原生文字页核对提取结果。期望值独立保存，不由待测解析器生成。

这些逐字金样检查正文提取、标题与段落归一化。插图与漫画另有结构和渲染测试；富文本样式与固定版式不要求原样重建。

## 标题、目录与段落结构

`structure` 套件使用独立编写的 EPUB 2 / 3、Markdown、DOCX、TXT 和原生 PDF 夹具。检查 URL 编码的书脊路径、同一 XHTML 内不同锚点、目录层级、元数据保存后的字符位置、HTML 实体、占位 Start 目录回退、目录与正文同文件、转换书籍页眉去重、正文伪标题过滤，以及 PDF 物理换行合并与真实缩进分段；整体缩进/居中的引文续行按局部坐标判断，同时保留有段距或句末证据的独立段落。期望章节和正文直接写在测试中，不由解析器生成。

`documents` 是可选的私有样书回归套件。把有权测试的 EPUB/PDF 放入目标应用 external-files 下的 `import-samples`，即可逐本导入、生成目录、点击章节、检查所有行/栏的边界和正文区间，并保存原生截图。独立的 `expectations.json` 可指定逐项目录顺序、禁止伪章节、唯一标题以及标题后同页的正文片段；`readingPoints` 可指定人工选取的正文位置，逐点截图复核；期望值应人工对照原书 NCX/导航与正文编写。有效原目录不应被数字节号或内部注释替代，印刷目录不能成为另一组正文标题。书籍、配置和提取正文不会进入源码或 APK；阅读样书截图必须再人工检查，不能只看目录条数和成功提示。

`migration` 检查旧版文字书和保存原文件的书各自如何升级。私有 `import-samples/migration.json` 指定 `file`、期望 `chapters` 数和正文 `anchor`。测试无选择器本机修复、清理印刷目录与重复标题、保留数字节号、阅读位置及书签，以及补充相同原文件后恢复原目录与插图且不增加书库条目。不同文件不能覆盖旧书。文字副本不能凭空恢复未保存的原页，界面必须说明这一边界。

`reading-revision` 从没有原文件且已经合并错误的旧文本副本出发，核对作者字段、重复 HTML 文件名、前言标题与无“目录”标签的点引导目录残留。另检查主菜单顺序、设置面板尺寸、预设内五档冷暖的逐档像素差异、三档实际窗口亮度与跟随系统、独立夜间/深色，以及底部与左右外缘等宽、顶部仍保留系统信息栏。使用日期和英文的实际原生绘制词距检查异常空白，并用位图字形间隙校准，不能只检查字符区间连续。

## 分类检测与可重放自动化

`quality` 使用 10 组独立中英文、法语、日语混排、阿拉伯文、日期、版权、诗歌、技术文件名和省略号文本，组合五种窗口、三种字号、单双栏，共 300 轮。HTML 内联标签分割位置变化后，正文必须与独立金样一致；合法诗歌换行、元数据和技术书文件名必须保留。另注入版权字段串接、印刷目录、HTML 文件头、重复标题和原生异常拉伸，验证检测器确实能够报错；不能用“检查器始终返回成功”的实现通过。

`BookDiagnostics` 把问题定位到原始 EPUB 文档/锚点或 PDF 页、提取块、字符位置、阅读页与绘制行。字符越界、空页和异常空格是错误；来源不足的疑似结构问题标为 `review`，供人工对照原件，不据此自动删正文。`DocumentEvidence` 为每本私有书保存 `*-audit.json`，需要审查其中的待核对项。

对齐决策以段落为单位。保留原生换行位置，按段落计算可接受的词间伸展，再用原生实际绘制调用核对；只对伸展超限的段落回退自然对齐。插入故障另有位图字形空隙的独立校准，不能仅依赖插入光标坐标。标题、元数据和预格式文本按各自语义处理。报告记录 `bounded-justification`、`excessive-word-spacing` 等决策原因。Android 的绘制阶段额外词距与字符插入坐标分开处理，参见 [AOSP TextLine](https://android.googlesource.com/platform/frameworks/base/+/5da73506b3e48f3af00dc92702267451f78f2e44/core/java/android/text/TextLine.java)。旧书修复另输出规则、输入位置与改前/改后片段；没有可核对证据的文件名、孤立省略号和未知单词保留。

先按贡献指南构建 app 和测试 APK，然后在专用可清空模拟器上执行：

```sh
python3 tools/verify_reader.py --serial YOUR_EMULATOR_SERIAL --allow-reset-test-data --install
```

脚本只操作指定模拟器，串行执行分类、结构、分页、交互、窗口和图文矩阵。每轮先清理同名旧报告，进程崩溃或缺少新报告均判失败；输出 `local/verification/reader-quality/summary.json`。首次失败保存输入、审计与源位置，并给出包含 seed/profile/font/columns 的重放命令。可用 `--private-corpus /path/to/authorized-books` 加入私有书籍及独立期望；原始证据保持本地。`--suite quality --seed 2 --profile 1 --font 32 --columns 2` 可单独重放一个布局条件。

## 屏幕参数与整屏均匀性

`screen` 通过真实硬件加速窗口与 PixelCopy 读回材质输出，使用 12×8 个位置相同的纸面、灰阶和实心墨块。三种材质、五档冷暖、三档灯光、夜间/深色和五个倾角组合成 900 个条件，三档对比度均衡穿插。另检查七个开启照明的轴向/对角倾角，以及 3408×2272、1440×960 和 960×1440 的实际渲染尺寸与密度。

测量在独立的线性 sRGB 数值上进行：关闭光感时各纸面块亮度范围小于 0.002、色差通道范围小于 0.002；同组五档冷暖的平均亮度漂移小于 0.0008；实心墨块之间亮度范围小于 0.0001。开启光感仍须保持有界受光。检查灰阶顺序和细纹理存在，避免用纯色空帧通过。每帧带独立标记、等待提交并核对读回身份；标记区域不参与任何测量。注入空间渐变、不均匀墨色和随暖色增加亮度的错误着色器，确认检测器会拒绝错误。数值是数字画面的相对量，不是实机亮度、色温或色准测量。

`screen-report.json` 记录全部条件和失败位置；`--suite screen --case 0` 可重放报告中该条件所属的五档冷暖组、尺寸与校准控制。原生控件另验证对比度的可发现性、持久恢复、阅读锚点、照明关闭与系统减少动态。报告、合成测试卡和截图仍保持本地。冷暖的亮度约束按 [Android AGSL 的线性颜色空间](https://developer.android.com/reference/android/graphics/RuntimeShader#agsl-and-color-spaces) 处理；验收计算独立于着色器实现。

## 原生分页与位置

`responsive300` 在 Android 原生文本与 Canvas 上执行 25 组窗口 × 三档系统字号（1.0 / 1.3 / 2.0）× 中英文 × 纯文字/插图，共 300 个条件。覆盖 320–440dp 常见手机、短横屏、小米平板参考窗口、分屏和扣除安全留白后的布局断点。每个条件核对源字符连续覆盖、正文与插图边界、正文锚点、菜单标签完整性、手机至少 36dp、平板至少 48dp 的独立参数点击区域与文件列表分页；保存选定条件的原生栅格。检测器另注入丢失末段、隐藏标签和过小点击区域，确认错误不会被忽略。

菜单箭头另外从原生栅格提取实际墨迹上下边界，核对其中心与行中心、返回栏中心的误差；覆盖长标签换行、滚动、中英文及三档系统字号。注入旧版按字号定位的文字箭头，确认检测器能拒绝本次报告的偏下问题。

`responsive-window` 通过真实 WindowManager 切换手机、小平板、大平板及分屏窗口，检查系统栏留白、菜单滚动与触摸、设置面板尺寸、全部菜单页、文件导入入口、系统非线性 SP 换算和字号往返的正文锚点。反馈只在本机填写测试草稿，检查软键盘覆盖与关闭返回，不向反馈服务提交。窗口像素和 dpi 为合成测试参数，不代表对应小米机型的出厂逻辑密度。

```sh
python3 tools/verify_reader.py --serial YOUR_EMULATOR_SERIAL --allow-reset-test-data --install --suite responsive300 --suite responsive-window
```

报告包含失败条件和重放命令；`--suite responsive300 --case 216` 重放一个排版条件，`--suite responsive-window --case 0` 重放一个真实窗口。原生截图与报告保留在本地忽略目录。

在 Android 的真实 `StaticLayout` 上组合横竖屏、三种字号、三档行距、单双栏和宋体/黑体，共 72 种条件，使用中英文混排、长链接、中文标点与补充平面字符检查：

- 所有栏的源字符区间从 0 连续覆盖到正文末尾，相邻区间没有空隙或重叠。
- 按阅读顺序重新连接所有区间，必须与输入逐字相等，SHA-256 也必须一致。
- 每栏行高不超过可读区域，每行水平边界不越出栏宽。
- 行边界不拆开 UTF-16 代理对；中文闭标点不出现在行首，开标点不留在行尾。
- 从正文采样的位置能映射回包含它的页面。

导入交互测试另外检查字体、字号变化后当前正文锚点仍在屏幕内、跨书阅读位置、段末孤字，以及系统选择器成功、取消、重复与损坏文件。

`anchors` 使用私有中英文长书，各取三处正文位置，每处反复调整字号、字体、行距和栏数，再还原。共 288 次布局变化均须保留同一个源字符位置、落在包含该位置的页上，往返后回到原页；另通过真实 WindowManager 旋转、Android 字体缩放和重开 Activity 验证保存恢复。期望锚点在操作前固定，不能从操作后的页面顶部重新生成。

`viewport` 套件通过 WindowManager 实际切换 3408×2272 / 320 dpi、3240×2160 / 480 dpi、2272×3408 / 400 dpi、1920×1200 / 320 dpi 和 1280×800 / 320 dpi。它显示系统栏，检查安全边距、正文范围、源位置保留和菜单边界；短窗口还滚动菜单并点击设置。系统字体缩放按 Android 的非线性 SP 换算核对，不能简单把字体乘以缩放比例。

`comics300` 生成 30 份本地样书：10 个 CBZ/图片 ZIP 漫画、10 个多插图 EPUB 和 10 个彩色插图 PDF；每份分别跑过 10 组横竖屏尺寸、密度、安全边距、系统字体缩放、字号、行距、单双栏和字体组合，共 300 轮。它核对漫画文件名自然排序、逐图单页、所有文本范围连续、页面不溢出、所有彩色图片转成不超过 16 阶的中性灰、源插图和压缩包 SHA-256 不变，并做一次本机持久导入、打开与实际翻页截图。另运行 `viewport` 套件，通过真实 WindowManager 切换五种窗口尺寸，检查系统信息栏、四周空白、安全边距、明亮中性底材、短窗口菜单与清洁终帧。报告和合成漫画截图保存在本地忽略目录 `local/verification/comics-300/`；这些合成证据不随源码发布。

清洁终帧检查将同一静止页面在多次往返翻页、完整刷新和关闭菜单后的截图逐像素比较。它用于发现旧字、面板轮廓等残留；过渡中的短暂墨迹变化另行检查，不要求每个中间帧与终帧一致。

设置、反馈与材质交互由 `experience` 原生测试覆盖。人工检查原生截图与实际切换过程，用于判断材质层次、触控可发现性和灯光观感；像素统计不替代视觉判断。

## 能保证到哪里

这套检查为仓库样例与测试矩阵提供可复现证据，不能证明所有书籍和设备都正确。复杂 PDF 的阅读顺序取决于其文本层，复杂分栏、公式、表格与竖排不保证精确重建；扫描件 OCR 会出错，需要核对原页。复杂 EPUB 样式和图片布局也不会原样保留。CBR/RAR 漫画压缩包目前不支持。新增失败样本应先缩减为可合法分享的夹具，再补真值与回归测试。

字形回退依赖设备字体。字符保留与字形正确显示分别验证；用户导入字体的版权由用户保留。小米 Pad 9 Pro Max 的实际字体、密度、系统文件选择器与触控仍需实机验收。

构建与执行命令见 [CONTRIBUTING.md](../CONTRIBUTING.md)。原始报告、截图和本地设备状态不随源代码发布。

## 扫描识别与长期保存

`library` 套件用原生 Canvas 绘制独立的简体、繁体、英文位图扫描页，确认无文本层后导入，按人工句子核对识别结果和章节。另检查矢量插图、源页锚点、识别检查点复用、原文件 SHA-256、有效的超过 50 MiB PDF、超限失败不修改旧书、无文件选择器重排、阅读位置/书签保留、旧版文字书整理，以及独立备份在空书库中的恢复。识别采用完整精度 PP-OCRv5 server 模型，原生分割提取行坐标，不对扫描字形强行简繁转换。路径越界与不完整备份必须在提交前失败。运行 OCR 验证时关闭专用模拟器网络，避免把模型下载误当成随包离线能力。

`backup` 套件从真实 Android DocumentsUI 选择本地 Downloads/Paperis-Backup-Test 文件夹并授予持久读写权限，通过应用内任务导入/重排、写入备份并读回校验；检查 `.partial` 不会被当成完成备份、授权与文件夹选择在 Activity 重建后保留。另导入多页扫描 PDF，离开应用时保存并暂停，返回后自动续做，期间不申请通知权限、不产生通知或运行通知服务。手动暂停后移除所选源文件，再验证从应用内原件与已完成识别页续做。仅在专用可清空设备运行。备份恢复的内容一致性检查与界面人工检查分别进行，不把成功提示当成保存成功的证据。

`source` 套件在手机和大平板窗口直接打开保存的 PDF 原件，从实际截图独立寻找纸页边界，检查页比例、文字、矢量图形和灰度转换，并通过真实触摸点击原页翻页。空白窗口必须被检测器拒绝；不再用整屏白色像素比例判断 PDF 是否完整，以免把正确的留白适配误报为空页。源文件仍保留完整页面，供核对 OCR 与复杂图表。

## 屏幕行为

`screen-behavior` 在正式 release APK 上验证自动、纸感、轻快三档刷新。对同一正文的稳定终帧、连续往返翻页和深浅色往返逐像素比较，核对在途请求时长、最终目标和外观的柔和过渡；等待实际 GPU 帧提交后取样。另验证手机和平板的真实显示旋转、锁定/自动、重新启动恢复，前台常亮、文件页释放、回桌面释放和返回恢复，以及系统减少动态与全局休眠时间保持。刷新时长是视觉模拟参数，不是面板硬件刷新率。
