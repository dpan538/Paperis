# 文本重排如何验证

重排分成两个可独立检查的阶段：从文档提取可读正文，以及把正文分配到行、栏与页。页面看起来整齐不足以证明文字准确。

## 解析后的正文

`androidTest/assets/fixtures/golden/expected.txt` 是人工编写的文本真值，包含中文、英文、数字、标点、补充平面汉字和 emoji。对应的 UTF-8、UTF-16 LE / BE、GB18030、Markdown、HTML、EPUB 与 DOCX 小样应逐字产生相同结果。

EPUB 故意让文件名顺序与书脊顺序相反，以检查章节是否按书脊连接。HTML 含不应进入正文的 script/style。PDF 另用已知内容的原生文字页核对提取结果。期望值独立保存，不由待测解析器生成。

这些测试检查当前“纯文本重排”的约定，包括标题与段落归一化；不要求保留原书图片、富文本样式或固定版式。

## 标题、目录与段落结构

`structure` 套件使用独立编写的 EPUB 2 / 3、Markdown、DOCX、TXT 和原生 PDF 夹具。检查 URL 编码的书脊路径、同一 XHTML 内不同锚点、目录层级、元数据保存后的字符位置、HTML 实体、占位 Start 目录回退、目录与正文同文件、转换书籍页眉去重、正文伪标题过滤，以及 PDF 物理换行合并与真实缩进分段。期望章节和正文直接写在测试中，不由解析器生成。

`documents` 是可选的私有样书回归套件。把有权测试的 EPUB/PDF 放入测试应用 external-files 下的 `import-samples`，即可逐本导入、生成目录、点击章节、检查所有行/栏的边界和正文区间，并保存原生截图。书籍与提取正文不会进入源码或 APK；阅读样书截图必须再人工检查，不能只看目录条数和成功提示。

## 原生分页与位置

在 Android 的真实 `StaticLayout` 上组合横竖屏、三种字号、三档行距、单双栏和宋体/黑体，共 72 种条件，使用中英文混排、长链接、中文标点与补充平面字符检查：

- 所有栏的源字符区间从 0 连续覆盖到正文末尾，相邻区间没有空隙或重叠。
- 按阅读顺序重新连接所有区间，必须与输入逐字相等，SHA-256 也必须一致。
- 每栏行高不超过可读区域，每行水平边界不越出栏宽。
- 行边界不拆开 UTF-16 代理对；中文闭标点不出现在行首，开标点不留在行尾。
- 从正文采样的位置能映射回包含它的页面。

导入交互测试另外检查字体、字号变化后当前正文锚点仍在屏幕内、跨书阅读位置、段末孤字，以及系统选择器成功、取消、重复与损坏文件。

`viewport` 套件通过 WindowManager 实际切换 3408×2272 / 320 dpi、3240×2160 / 480 dpi、2272×3408 / 400 dpi、1920×1200 / 320 dpi 和 1280×800 / 320 dpi。它显示系统栏，检查安全边距、正文范围、源位置保留和菜单边界；短窗口还滚动菜单并点击设置。系统字体缩放按 Android 的非线性 SP 换算核对，不能简单把字体乘以缩放比例。

清洁终帧检查将同一静止页面在多次往返翻页、完整刷新和关闭菜单后的截图逐像素比较。它用于发现旧字、面板轮廓等残留；过渡中的短暂墨迹变化另行检查，不要求每个中间帧与终帧一致。

设置、反馈与材质交互由 `experience` 原生测试覆盖。人工检查原生截图与实际切换过程，用于判断材质层次、触控可发现性和灯光观感；像素统计不替代视觉判断。

## 能保证到哪里

这套检查为仓库样例与测试矩阵提供可复现证据，不能证明所有书籍和设备都正确。复杂 PDF 的阅读顺序取决于其文本层，分栏、公式、表格、竖排与扫描件不在当前准确重排承诺内。复杂 EPUB 样式和图片布局也不会原样保留。新增失败样本应先缩减为可合法分享的夹具，再补真值与回归测试。

字形回退依赖设备字体。字符保留与字形正确显示分别验证；用户导入字体的版权由用户保留。小米 Pad 9 Pro Max 的实际字体、密度、系统文件选择器与触控仍需实机验收。

构建与执行命令见 [CONTRIBUTING.md](../CONTRIBUTING.md)。原始报告、截图和本地设备状态不随源代码发布。
